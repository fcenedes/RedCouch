# API Reference

RedCouch's Rust API documentation is generated by `rustdoc` from the source code.

## Generating API Docs Locally

```bash
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --open
```

This builds the API documentation and opens it in your browser. The generated docs cover all public types, functions, and modules in the `red_couch` crate.

## Key Modules

| Module | Description |
|---|---|
| `red_couch` | Crate root — module registration, TCP listener, connection handling |
| `red_couch::protocol` | Binary protocol types, opcode enum, request parser, response encoder |
| `red_couch::ascii` | ASCII text protocol parser and command types |
| `red_couch::meta` | Meta protocol parser, flag validation, command types |

## Integration with the Documentation Site

When the documentation site is published to GitHub Pages, the API reference can be linked or embedded alongside the book. The GitHub Actions workflow builds both the mdBook site and the rustdoc output, placing the API docs at `/RedCouch/api/`.

To browse the API reference on the published site, navigate to the `/api/` path under the documentation site URL.

## CI Validation

The CI pipeline validates that API documentation builds cleanly:

```bash
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps
```

This runs on every push to `main` and on pull requests, ensuring documentation stays in sync with the code.
